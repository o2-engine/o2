## Джобы
`o2::JobSystem` — синглтон-пул рабочих потоков, выполняющих единицы работы из очередей с приоритетами. Глобальная точка доступа — макрос `o2Jobs`. Джобы держатся через [`o2::SharedRef<Job>`](/Docs/ru/Architecture/Utils/threading.md), поэтому хендл безопасно хранить и удалять в любом потоке.

## Планирование
- **Schedule(body, priority, thread)** — создаёт и сразу отправляет джобу на выполнение, возвращает её хендл.
- **CreateJob(body, priority, thread)** + **Submit(job)** — сначала создать (чтобы настроить зависимости), затем отправить.
- **AddDependency(job, dependency)** — `job` стартует только после завершения `dependency`; вызывать до отправки `job`.
- **ExecuteMainThreadJobs(quotaSeconds)** — на главном потоке выполняет джобы из очереди `JobThread::Main`, пока очередь не опустеет или не будет превышена временная квота (`< 0` — без лимита). Best-effort: выполняющуюся джобу не прерывают, поэтому квота может быть превышена не более чем на одну джобу.
- **WaitForIdle()** — блокируется, пока остаются незавершённые параллельные (`JobThread::Any`) джобы.
- **Initialize(workersCount)** / **Shutdown()** — запуск / остановка пула воркеров (`workersCount < 0` использует аппаратные потоки − 1, минимум 1). Управляется приложением, а не игровым кодом.

## o2::Job
- **onCompleted** — колбэк [`o2::Function<>`](/Docs/ru/Architecture/Utils/function.md), вызываемый сразу после завершения тела, на выполняющем потоке.
- **DependsOn(dependency)** — объявляет предусловие; задавать зависимости до отправки.
- **Then(body, priority, thread)** — планирует продолжение, выполняемое после завершения этой джобы, возвращает его хендл.
- **Wait()** — блокирует вызывающий поток до завершения джобы. Нельзя вызывать на джобе `JobThread::Main` из главного потока — дедлок.
- **IsDone()** / **IsRunning()** / **GetPriority()** / **GetThread()**.

## Приоритеты и потоки
- **JobPriority** — `Low`, `Normal`, `High`, `Critical`. Джобы с более высоким приоритетом берутся воркерами первыми.
- **JobThread** — `Any` выполняется в пуле параллельных воркеров; `Main` — только на главном потоке, вычерпывается через `ExecuteMainThreadJobs`.

**Контракт изоляции:** тело `JobThread::Any` не должно трогать разделяемое состояние `o2::Ref` сцены/ассетов, которое параллельно меняет главный поток (счётчик `o2::Ref` не атомарен). Работа, которой нужны сцена или ассеты, должна выполняться на `JobThread::Main`. См. [многопоточность](/Docs/ru/Architecture/Utils/threading.md).

## Однопоточные платформы
На платформах, которые не могут создавать потоки ОС — сборка WebAssembly без pthreads — система работает в **кооперативном режиме**: `Initialize` запускает **ноль воркеров** (`GetWorkersCount() == 0`), джобы `JobThread::Any` попадают в очередь главного потока и вычерпываются на нём через `ExecuteMainThreadJobs` / `WaitForIdle`. Каждый покадровый прогон обрабатывает только те джобы, что уже были в очереди на его старте, поэтому корутина, которая перепланирует саму себя, продвигается на один шаг за кадр, а не блокирует кадр. Тот же API джоб/корутин используется без изменений — меняется лишь то, что выполнение последовательное. `Initialize(0)` включает этот режим явно на любой платформе. ([Планировщик корутин](/Docs/ru/Architecture/Utils/coroutines.md) там же гоняет `WaitTime` из кадра, а не из потока-таймера.)

<details>
<summary>Пример</summary>

```C++
// Параллельная работа на воркерах, затем продолжение на главном потоке
auto job = o2Jobs.Schedule([]() { /* тяжёлые вычисления, без обращений к сцене/ассетам */ },
                           o2::JobPriority::Normal, o2::JobThread::Any);

job->Then([]() { /* применить результаты к сцене */ }, o2::JobPriority::Normal, o2::JobThread::Main);

// Зависимости: b выполняется только после a
auto a = o2Jobs.CreateJob([]() { /* ... */ });
auto b = o2Jobs.CreateJob([]() { /* ... */ });
b->DependsOn(a);
o2Jobs.Submit(a);
o2Jobs.Submit(b);

o2Jobs.WaitForIdle();
```
