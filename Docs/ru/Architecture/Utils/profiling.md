# Документация по профилированию

## Описание
В движке есть встроенный покадровый профайлер `o2::NanoProfiler` и экранная панель, которая его
показывает, — `o2::ProfilerWidget`. Оба включаются в сборку опцией CMake `O2_PROFILER` (по умолчанию
включена), она задаёт `O2_PROFILER_ENABLED`; при выключенной опции классов не существует, а все
макросы профилирования разворачиваются в пустоту.

Это лёгкий, всегда доступный профайлер. Для полной таймлинии с потоками, локами и GPU-зонами в
движке есть клиент [Tracy](https://github.com/wolfpld/tracy), включаемый опцией `O2_TRACY`, — те же
макросы `PROFILE_*` кормят оба.

## Макросы
Ставятся в измеряемом коде; ничего не стоят, когда профайлер выключен из сборки или не пишет.

- **PROFILE_SAMPLE_FUNC()** — измеряет текущую функцию, имя берётся из `__PRETTY_FUNCTION__`.
- **PROFILE_SAMPLE(id)** — измеряет текущую область под заданным именем. Имя должно быть строковым
  литералом или иначе иметь статическое время жизни: области различаются по указателю.
- **PROFILE_SAMPLE_COLOR(id, color)** — то же, с явным цветом в Tracy.
- **PROFILE_NEW_FRAME()** — закрывает кадр профайлера и открывает следующий. Вызывается из
  `Integration::ProcessFrame`; ставить только там, где не открыта ни одна область.
- **PROFILE_BIND_THREAD()** / **PROFILE_UNBIND_THREAD()** — делает вызывающий поток записываемым.
  Вызывается `Integration` для главного потока.
- **PROFILE_FRAME()**, **PROFILE_THREAD(name)**, **PROFILE_FIBER_ENTER/LEAVE**, **PROFILE_INFO** —
  только для Tracy.

## `o2::NanoProfiler`
Иерархический покадровый профайлер. Каждая область пишется в заранее выделенный массив как
`(name, parent, begin, end)`, а готовый кадр публикуется обменом двух буферов — кадр не стоит ни
одной аллокации и ни одного копирования. Времена — наносекунды от начала кадра.

- **BeginSample(name)** / **EndSample()** — открыть и закрыть область; `SampleScope` — RAII-форма.
- **ExcludeScope** — приостанавливает запись на время своей области. Панель профайлера оборачивает
  в неё своё обновление и отрисовку, поэтому никогда не приписывает игре собственную стоимость.
- **NextFrame()** — публикует записанные области и начинает новый кадр. Области, открытые на границе
  кадра, на ней и закрываются.
- **SetEnabled(enabled)** / **IsEnabled()** — запись переключается вместе с видимостью панели и
  вступает в силу со следующего кадра.
- **BindThread()** / **UnbindThread()** — пишет только привязанный поток. В любом другом потоке
  область профилирования — одна проверка на null, поэтому рабочие потоки могут держать свои макросы
  и не гоняться за состоянием профайлера.
- **GetFrameSamples()**, **GetFrameSamplesCount()**, **GetFrameDuration()**,
  **GetFrameDroppedSamples()** — последний завершённый кадр.
- **AggregateFrame(buffer, capacity)** — сводит кадр к собственным временам по именам (время области
  минус время вложенных в неё). Без аллокаций; не поместившиеся имена суммируются в последнюю запись
  `Other`.
- **DumpLog()** — выводит сведённый кадр в лог.

Ограничения: `maxFrameSamples` областей на кадр и `maxDepth` вложенности; всё сверх отбрасывается и
считается в `GetFrameDroppedSamples()`.

### Область редактора
Области, взятые внутри [editor scope](/Docs/ru/Editor/editor.md), отбрасываются. В редакторе так
остаётся ровно игровая работа — и `EditorApplication::UpdateScene`, и отрисовка окна Game выходят из
области редактора, — поэтому панель показывает игру и игнорирует собственный UI редактора.

## `o2::ProfilerWidget` и `o2::ProfilerOverlay`
`ProfilerOverlay` владеет панелью и живёт в `Integration`; получить его можно через
`o2::ProfilerOverlay::InstancePtr()`. Он показывает и прячет панель по **F12** или по **долгому тапу
в левом верхнем углу экрана** и вместе с ней переключает запись профайлера.

В игре панель рисуется поверх всего экрана, после отладочных примитивов кадра. В редакторе её
показывает кнопка `Profiler: on/off` на верхней панели окна Game, оно же и забирает отрисовку: `GameWindow::GameView::Draw` вызывает `DrawIn(area)` со своим прямоугольником, поэтому
панель стоит в левом верхнем углу того окна, содержимое которого она и измеряет, и не закрывает
остальной редактор. Кто вызвал `DrawIn` в кадре, тот и рисует панель в этом кадре; без вызова оверлей
возвращается к отрисовке на весь экран.

Панель показывает:
- таймлинию профайлера: по колонке на кадр, сложенную из собственных времён областей. **Наведение
  курсора останавливает таймлинию и детализирует кадр под курсором** — у каждой полосы появляется
  подпись с временем и именем области; подписи сложены снизу вверх у нижнего края графика, так же как
  и полосы, поэтому выноски короткие и не пересекаются. Кадры правее курсора на замороженном графике
  не рисуются. Без курсора детализируется последний кадр;
- временной ряд по каждой метрике с текущим значением и диапазоном по ряду;
- счётчики объектов, опрашиваемые несколько раз в секунду;
- кнопку `Base`, которая переключает значения на разницу с зафиксированной базой. И она, и уголок
  ресайза подсвечиваются под курсором.

Панель висит на левом верхнем углу хоста, вплотную к нему. **Перетаскивание уголка в правом нижнем
углу меняет её размер**: угол идёт за курсором по обеим осям, левый верхний угол остаётся на месте.
Растягивается только таймлиния — шире панель значит шире колонки кадров, выше значит выше график, а
строки подписей сохраняют свою высоту и размер шрифта.
Размер ограничен между `GetMinContentSize()` (пиксель на кадр плюс строки подписей) и
`GetDesignSize()*maxSizeFactor`; из кода то же делает `SetContentSize()`.

`GetOverallStatus()` оценивает все зарегистрированные метрики и счётчики вместе; на панели он не
рисуется, игра может использовать его, чтобы реагировать на затяжную просадку кадра.

Встроенные метрики — FPS, миллисекунды кадра (весь кадр профайлера, то есть апдейт и отрисовка
вместе), draw calls и отрисованные примитивы. Последние две берутся из
`Render::GetSceneDrawCallsCount()` и `GetSceneDrawnPrimitives()`, которые не считают всё нарисованное
внутри области редактора: в редакторе это значит, что числа описывают окно Game, а не UI редактора
поверх него.

Счётчики блока `Entities` описывают, из чего состоит сцена. Они собираются одним проходом по акторам
сцены несколько раз в секунду, и считаются только акторы, реально находящиеся на сцене, поэтому
собственные виджеты редактора в них не попадают:
- **Actors** — акторы на сцене, включая UI-виджеты. Если число только растёт между двумя одинаковыми
  состояниями игры — что-то не освобождается
- **UI** — сколько из них виджеты
- **Sprites** — `ImageComponent` плюс слои виджетов, рисующие спрайт
- **Texts** — слои виджетов, рисующие текст
- **Animations** — `AnimationComponent` и `AnimationStateGraphComponent`
- **Particles** — эмиттеры частиц
- **Models** — 2D-, 3D-, скиннед- и примитивные меши
- **Spines** — скелеты Spine
- **Lights** — источники света

Игра добавляет свои метрики и счётчики:

<details>
<summary>Пример</summary>

```C++
if (auto overlay = o2::ProfilerOverlay::InstancePtr())
{
    o2::PerfMetricSettings settings;
    settings.goodValue = 100.0;  // меньше этого — нормально
    settings.badValue = 1000.0;  // больше этого — метрика плохая

    overlay->AddMetric(o2::PerfMetric("Enemies", []() { return (double)CountEnemies(); }, settings,
                                      { 100.0, 500.0, 2000.0 })); // шаги масштаба графика

    overlay->AddCounter(o2::PerfCounter("Bullets", []() { return CountBullets(); }, settings));
}
```
</details>

Вся панель рисуется одним мешем плюс подписи `o2::Text` из пула, которые перестраиваются только
тогда, когда действительно меняются их текст, рамка или цвет.
