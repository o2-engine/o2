## Менеджмент памяти
Основной механизм управления временем жизни объектов — собственные умные указатели `Ref<>` и `WeakRef<>` со счетчиком ссылок.

Счетчик ссылок (`RefCounter`) внешний, но объект хранит указатель на него, наследуясь от `RefCounterable`. Это позволяет преобразовать обычный «сырой» указатель обратно в `Ref<>`.

Объекты создаются через макрос `mmake` (managed make): он выделяет один блок памяти под счетчик и объект (счетчик перед объектом, cache-friendly) и возвращает `Ref<>`.

<details>
<summary>Пример</summary>

```C++
class MyObject: public o2::RefCounterable
{};

Ref<MyObject> obj = mmake<MyObject>();
WeakRef<MyObject> weak = obj;

MyObject* raw = obj.Get();
Ref<MyObject> obj2 = Ref(raw);
```
</details>

- `Ref<>` — сильная ссылка, владеет объектом. Когда сильных ссылок не остается, объект уничтожается.
- `WeakRef<>` — слабая ссылка, не влияет на время жизни. Методы `IsExpired()`/`IsValid()` и `Lock()` для получения `Ref<>`.
- Касты между типами ссылок: `DynamicCast<T>(ref)` и `StaticCast<T>(ref)`.
- Для forward-объявленных типов используются макросы `FORWARD_CLASS_REF`/`FORWARD_REF_IMPL`.

## Отслеживание аллокаций
Для ручных аллокаций переопределены функции new() с параметрами исходника и номера строки. Для удобства они спрятаны в макрос mnew (managed new), который регистрирует аллокацию (аналогично `mmalloc`/`mfree` для сырой памяти).

Список мест аллокаций с суммарными размерами выводит `o2::MemoryManager::DumpInfo()`. Так можно вычислить утечки и расход памяти. Работает при включенном `ENABLE_MEMORY_MANAGE`.

## Отладочный анализ памяти
При включенном `ENABLE_MEMORY_ANALYZE` работает отладочный анализатор `MemoryAnalyzer`: он строит дерево владения объектами по ссылкам (`BuildMemoryTree()`), показывает размеры и подсвечивает возможные утечки и циклические ссылки. Объекты он не уничтожает — служит только для анализа. В редакторе есть окно для просмотра этого дерева памяти.
