## Assets, система ассетов
Каждый ресурс игры - это ассет. Они попадают в сыром виде в папку с ассетами, и перед запуском собираются определенным образом в конечный формат.

Так, например, на этапе сборки происходит упаковка текстур в атласы и их сжатие.

Каждый ассет содержит мета-данные, в которых определен уникальный идентификатор и другие параметры. Эти мета-данные леэат рядом с ассетом, имеют такое же имя файла, но с расширением .meta.

Сущности в движке могут ссылаться на ассет как по пути, так и по идентификатору. Второй способ является основным. Идентификатор остается неизменным если ассет переместить или переименовать. Таким образом ассеты можно перемещать как угодно и ссылки останутся неизменными.

### Система ассетов
Для базовой работы с ассетами в движке есть отдельная подсистема `o2::Assets`, с быстрым доступом по макросу `o2Assets`.

Она содержит в себе кеш ресурсов, дерево жоступных ассетов и имеет функционал по работе с ассетами: создание экземпляра, перемещение, удаление и тд. `GetCachedAssets` возвращает загруженные ассеты кеша.

### Базовый класс ассета Asset
Он содержит в себе базовую информацию об ассете: идентификатор, путь к ассету. А так же базовый функционал - загрузка, сохранение.

### Типы ассетов
Подтипы ассетов наследуются от базового `o2::Asset`:
- FolderAsset: папка с ассетами, которые можно получить
- ActorAsset: прототип актора
- SceneAsset: сцена
- AnimationAsset: анимационный клип
- AnimationStateGraphAsset: граф анимационных состояний
- AtlasAsset: атлас
- ImageAsset: картинка, ссылается на атлас
- VectorImageAsset: векторная картинка, файл `.svg`, рисуется треугольниками через `o2::VectorSprite`
- BinaryAsset: бинарный файл
- DataAsset: сериализованные данные, конфиги
- VectorFontAsset/BitmapFontAsset: векторный/растровый шрифт (базовый FontAsset), FontStyleAsset: стиль шрифта
- MaterialAsset, ShaderAsset (VertexShaderAsset/FragmentShaderAsset): материалы и шейдеры
- Mesh3DAsset, SkinnedModelAsset: 3D-меши и скиннед-модели
- SoundAsset: звук (wav, ogg, mp3, flac)
- SpineAsset, SpineAtlasAsset: скелет и атлас Spine
- JavaScriptAsset: JS скрипт 

### Векторная картинка, VectorImageAsset
`o2::VectorImageAsset` привязан к расширению `svg`. Сборщик копирует файл как есть (и запекает его меш, если просит мета, см. ниже); при загрузке он разбирается `o2::SvgParser` в `o2::VectorImage` (см. [Векторная графика](/Docs/ru/Architecture/LowLevel/render.md)). Загрузка не требует рендера и текстур, в атлас ассет не попадает.

- Мета (`VectorImageAsset::Meta`): `sliceBorder` (`BorderI`, в единицах изображения: left, bottom, right, top; top — верхняя сторона изображения) и `defaultMode` (`SpriteMode`) — тот же смысл, что в `ImageAsset::Meta`; `o2::VectorSprite` берёт их при назначении картинки; `scalableMesh` (`bool`, по умолчанию выключен) — картинка рисуется одним мешем под любой масштаб (`IsMeshScalable`); `rasterized` (`bool`, по умолчанию выключен) — её спрайты рисуются растрами из атласа векторных растров (см. [Векторная графика](/Docs/ru/Architecture/LowLevel/render.md)). Поверх них у ассета есть свойства `sliceBorder`, `defaultMode`, `scalableMesh` и `rasterized`, их правит окно Properties.
- Запечённый меш. Для картинки со `scalableMesh` сборщик (`VectorImageAssetConverter`) один раз тесселирует масштабируемый меш и пишет его рядом с собранным файлом (`GetBakedMeshPath`: `<файл>.svg.mesh`, `BakeMesh`); смена флага запекает или удаляет его, а после каждой сборки меш другой версии формата или тесселяции запекается заново, даже если SVG не менялся. При загрузке ассет берёт меш из файла без тесселяции (`IsMeshBaked`); файл другого текста SVG или другой версии формата пропускается с предупреждением, и картинка тесселируется один раз при первом использовании. Перекраска, изменившая картинку (ниже), тоже пропускает запечённый меш.
- `GetSize`, `GetImage`, `IsValid`, `GetError`, `GetWarnings`. Файл, который не является валидным SVG, даёт ассет с `IsValid() == false`, пустым изображением и без мешей; ошибка и предупреждения о неподдерживаемых элементах пишутся в лог ассетов один раз за загрузку.
- `GetMesh(pixelScale)` и `GetSlicedMesh(pixelScale, borders)` возвращают тесселированные треугольники (`o2::VectorImageMesh`) из кеша, общего для всех drawable этого ассета. Ключ — пиксельный масштаб, квантованный через `QuantizePixelScale` (степени двойки, диапазон 1/16..64), и для нарезанного варианта — бордеры; нарезанный меш получается разрезанием кешированного целого меша того же масштаба, без повторной тесселяции. В кеше до 32 мешей, он сбрасывается при смене изображения; используемые меши остаются живыми.
- `SetSource(svg)` заменяет изображение из текста, `GetSource` возвращает его, `Save` записывает обратно в файл.
- `GetVersion` меняется при каждой загрузке и не совпадает у двух загруженных ассетов, поэтому drawable по ней же замечает смену ассета. После `Assets::RebuildAssets` ассет перезагружается сам, если его id есть в списке изменённых; drawable сравнивают версию при отрисовке и перестраивают вершины.
- `SetImageRemap(remap)` (статическая) перекрашивает каждую картинку, загруженную после вызова: картинка передаётся функции вместе с путём собранного файла и может получить другие заливки, обводки и фигуры, тогда функция возвращает true; пустая функция - без перекраски, `ImageRemap` возвращает текущую. Уже загруженная картинка берёт её при `Reload`. Так темы редактора перекрашивают его графику ([темы](/Docs/ru/Editor/editor.md)).

### Ссылки на ассеты
Ссылка на ассет - это шаблонный класс `o2::AssetRef<AssetType>`, наследник нешаблонной базы `o2::BaseAssetRef`. Функционирует как типичный умный указатель.

Работу с ассетами корректнее вести через ссылки, во избежании дублирования загрузки ассетов
