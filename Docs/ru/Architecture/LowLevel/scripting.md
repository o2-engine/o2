## Скриптинг
В о2 встроен скриптовый движок JS с несколькими бекендами: QuickJS (по умолчанию), JerryScript и BrowserJS (JS-движок браузера в Emscripten-сборках). Бекенд выбирается CMake-опцией `O2_SCRIPTING_BACKEND`.

Скриптовым движком управляет подсистема `o2::ScriptEngine`, с быстрым доступом по макросу `o2Scripts`. Она хранит глобальное состояние его можно получить через `GetGlobal`. Может парсить и запускать скрипты (`Parse`/`Run`/`Eval`)

Так же он управляет подключением дебаггера.

### Библиотеки скриптов и данные
Скрипты компонентов (`o2::ScriptableComponent`) описывают по одному классу. Общий для них код лежит в обычных скриптовых ассетах и подключается `include(path)` (путь внутри ассетов, например `"Scripts/Game/Core/Board.js"`): файл выполняется в глобальной области один раз и повторно — только после изменения собранного файла; скрипты, подключающие друг друга, не зацикливаются; при отсутствии или ошибке файла `include` возвращает `false` и пишет причину в лог.

`o2.FileSystem.ReadFile(path)` (`undefined`, если файла нет), `WriteFile(path, text)`, `IsFileExist(path)` и `FileDelete(path)` дают скриптам простые текстовые файлы, например сохранение. Data-ассет доступен скриптам как JSON-текст: `JSON.parse(new o2.AssetRefDataAsset(path).Get().GetJson())`.

<details>
<summary>Пример</summary>

```js
include("Scripts/Game/Core/Board.js");

var campaign = JSON.parse(new o2.AssetRefDataAsset("Game/campaign.json").Get().GetJson());
var saved = o2.FileSystem.ReadFile("progress.json");
var progress = saved !== undefined ? JSON.parse(saved) : { level: 0 };
o2.FileSystem.WriteFile("progress.json", JSON.stringify(progress));
```
</details>

### Обертка скрипт-значения, o2::ScriptValue
Этот класс является универсальной оберткой любого скриптового значения. В нем может храниться как простой тип (number, string, bool ...), так и массивы, объекты и функции.

Для определения типа объекта используются функции-геттеры `IsArray`/`IsObject`, или `GetValueType`.

Так же класс имеет операторы конвертации в/из нужного типа

#### Объекты
Для обхектных типов есть функционал по получению property объекта: `GetProperty`, а так же перебор всех пропертей `ForEachProperties`. Так же можно добавлять и удалять проперти в объекте.

Есть функционал для прототипов объектов, можно получить или установить прототип: `Set/GetPrototype`

Так же есть функция `Construct` для конструирования обхекта из функции-конструктора

#### Массивы
Для работы с массивами есть функции получения элемента: `operator[int]` и `Set/GetElement`. А так же получение длины массива `GetLength()`. И добавление/удаление элемента в массиве: `Add/RemoveElement`.

Скриптовые значения сериализуются в `DataValue` и обратно (поля скриптовых компонентов в сценах и прототипах): массив остаётся массивом и пустым, а чтение массива заменяет значение, а не дописывает в него.

#### Функции
В переменной так же может быть функция, которую можно вызвать. Вызвать можно с передачей С++ параметров через шаблоны, тогда внутри они сконвертируются в скриптовые значения: `Invoke`. Либо сразу с уже заготовленными скриптовыми занчениями: `InvokeRaw`.

Так же при вызове функции можно задать параметр this первым аргументом

#### Биндинг классов и функций в скриптинг
Каждый объект, при включенном скриптинге может хранить в себе закешированное скриптовое значение на этот объект. Это скриптовое значение представляет из себя объект с нативным поинтером на себа внутри. Так же в нем есть поля, которые биндятся к скриптингу

Для каждого типа в рефлексии генерируется прототип, на который потом ссылкаются инстансы этого типа. То есть функции фактически хранятся в прототипе. Базовые классы становятся прототипами наследников. При множественном наследовании в цепочку прототипов встаёт только первая база; функции остальных баз (и их собственных баз на любой глубине) копируются в прототип наследника после регистрации всех типов, поэтому результат не зависит от порядка регистрации типов (он разный на разных платформах).
