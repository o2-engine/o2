## Pipeline. AI content pipelines window

Edits a `.pipeline` asset: a node graph that turns text, images and sounds into game assets with AI providers and local image/audio processing. Open it from the Assets window (double-click a pipeline asset, `Create/Pipeline` in the context menu makes a new one) or from `View/Show Pipeline`. The file is the AssetsLine pipeline document (JSON), the same one the AssetsLine web editor keeps, so a pipeline moves between the two unchanged.

![pipeline](pipeline.png)

The window is a canvas with node cards. The toolbar runs the whole graph (every branch end, so a chain that no finish node consumes runs too), stops a run, fits the view and imports an AssetsLine file; on the right, `Save all` writes what every finish and composer node shows into the assets (from the results on screen, generating nothing), and the gear opens the settings window: the AssetsLine link and the provider keys (Gemini, OpenAI, OpenRouter, ElevenLabs, Kling; stored in `Work/Pipelines/PipelineSettings.json`). The status line shows the executor log.

### Canvas
- Right-drag or the wheel pans and zooms (down to 1/40 of the natural size, enough for graphs of a few hundred nodes, and up to 4 times it); the wheel zooms and the right button pans over cards and their controls too; the zoom step follows the delta but never drops below a visible minimum, so the view answers a touchpad as readily as a wheel; a right click without a pan opens the menu of the card, link or canvas under the cursor. The view repaints its content only when something changed, but registers in the cursor system every frame - otherwise a view left alone would stop taking the mouse. `F` fits the graph, the camera is saved into the asset; a scale coming from the asset is clamped to the view range, and a graph with a neutral camera (zero position, scale 1) is fitted by the editor on open.
- Only the cards and links inside the view are updated and drawn; zoomed out past about 1/4 the cards stop drawing their controls (edits, buttons, sliders, toolbars, resize handles) while what the node produced - previews, drawings, the composer stage - stays in place, so panning a large graph stays smooth.
- Right-click on empty space opens `Add/<category>` with every node type (each item carries the node icon), plus `Paste` and `Select all`. Dragging a link into empty space opens the same menu filtered by compatible ports and connects the new node.
- Ports are marked by shape as well as colour: a circle for text, a square for image, a diamond for audio, a triangle for video - a link still reads with the colours turned down. Links are drawn as thin curves coloured by port type (text - blue, image - orange, video - purple, audio - teal); their thickness follows the zoom but never drops below one pixel. Double-click a link to add a bend point, drag the points, `Straighten` in the link menu removes them.
- Drag from an output port to an input port to connect; drag from a connected input to detach and re-route. Ports with a `+` accept extra inputs (composer layers, AI references): drop a link on `+` to add one, rename it in place, remove it with `-`.
- The canvas grid follows the snapping step: a line every 20 units and a stronger one every 100; zoomed out, the finest lines fade and the grid steps up by five (100, 500, ...). Cards are moved by the header and land on the grid points (the other selected cards keep their distance), and resized by dragging any edge or corner; a card never gets shorter than its content - neither on screen nor in the height a resize stores, which is taken at the width the resize ends with (a narrower card may wrap its rows taller). Box selection, `Ctrl+C/V/D`, `Delete`, `Ctrl+A`, `Ctrl+Z/Y` work as in the scene editor; every change is an undo action of the window.
- The dot before the play button carries the result state: green - up to date with the inputs, amber - there is a result but the inputs moved on, hollow - never produced anything, teal - running. The card outline speaks for selection (teal), running or queued (blue) and failure (red, the alert button shows the error); outlines follow the zoom but never drop below one pixel. A yellow badge counts provider retries. Sources and self-applying nodes have neither a play button nor a dot.

### Import from AssetsLine
The import button of the window toolbar reads a pipeline exported by AssetsLine: either the plain pipeline JSON or a bundle made with `Export with results…` (a ZIP with `pipeline.json`, `manifest.json` and the results under `results/`; the older JSON bundles are read too). Node types, configs, ports and links are the same on both sides, so the graph comes in as is; the bundled results become the node previews and freshness markers of the new asset (`Pipelines/<name>.pipeline`), so nothing has to be re-run to see them. A newer bundle also carries the parts of the per-port nodes, each restored as its own part result, and the files its source nodes read - they are written into the uploads folder, so the imported sources are not empty. Imported drawings of draw nodes keep their pixel size. If the open pipeline has unsaved changes, the import first asks once whether to save them; with either answer the imported pipeline opens.

Results and the cache are keyed by an id stored in the graph itself (`Work/Pipelines/cache/<id>/`), not by the asset: saving the pipeline under another name or duplicating the asset keeps its results. Assets saved before the id existed adopt their asset UID on the first open.

### AssetsLine sync
The project can be linked to an AssetsLine project (`Edit/Project/AssetsLine`, or the gear at the right of the window header). The dot on the gear shows the link state (none while sync is off): red - no connection (not connected, offline, error), blue pulsing - connecting, green - connected, green pulsing - a pass is running in either direction. Then the pipelines of one folder of `Assets` (`Pipelines` by default) and the AssetsLine project are one set: a pipeline made or edited on either side appears on the other, and so do results — whatever one side generated is available and up to date on the other without generating again.
- The dialog shows the state in its header (the same dot, the state and what was synced when, or what went wrong). Until the project is linked it asks for the server and the way to connect: **Browser** opens the AssetsLine page that asks which project to link and shows the code and the page address while waiting; **Access token** takes a token made in the AssetsLine settings (Settings → Connected editors). Once linked it shows the project and the account with **Disconnect**. The token is kept per user in `Work/Pipelines/sync/`, the link (server, project, folder, options) in the project settings.
- A synced pipeline saves itself a second after an edit, the way the web editor autosaves. Edits made on both sides are merged node by node; when both changed the same field, the later save wins. An unsaved pipeline is never overwritten: its remote changes wait until it is saved and are merged then.
- Renames and deletions travel both ways; a pipeline deleted on one side while edited on the other comes back.
- **Write results of finish nodes into the assets**: a result reaching a finish node from AssetsLine is written where the node writes it (`assetPath`, or `Generated/<download name>` for a pipeline made on the web).
- Sources taken from project assets are uploaded under an id derived from their content, so a changed asset is a changed source on the other side too.
- Sync works on macOS and in the web editor; the socket HTTP backend of Windows and Linux has no https.

### Nodes
Sources (text, image, audio), text tools (compose template, concat), AI nodes (text, prompt generator, image generation and edit, upscale, extract sprite, remove background (local and by the image model), video, sound effects, speech, music), image effects (draw, outline, shadow, gradient, colour, composer), audio processing and finish nodes. Toolbars that do not fit the card width wrap onto the next line (the draw tools, the composer tools). Each card holds the same controls as the AssetsLine node: model dropdowns with presets, prompts, seed inheritance, transparent background (white/black two-pass or chroma key with colour, tolerance, softness and spill sliders) and a result preview with a crop frame.

Every card is laid out the same way, result first: what the node produced (or, for a finish node, what reaches it) at the top, then the one field that is edited per run (the prompt, the instruction, the hint), then the action buttons, and last a folded `Parameters · …` row listing what it hides, always the model first (then the seed on the image cards, then the rest: transparency method, aspect and the like); clicking the row shows them at once and turns the arrow down, clicking again hides them (the fold is remembered per node and does not affect the cache). A card that fits its content grows and shrinks with the list; a card given a height by resizing changes it by exactly what its content adds or removes - the list, the transparent switch and the method rows, the extract parts - never snapped to the grid, so the pictures keep their size, as in AssetsLine; only the user's own resize drag sets the height. Local nodes whose controls are their work - the image effects and audio processing - keep them open under the result.

- **Draw** paints strokes over an optional background image: brush and eraser, colour palette and picker, size and opacity sliders, undo/redo/clear. The strokes are stored in the node config and composited over the background by the node.
- **Input | result.** The image-to-image cards (AI image edit, AI extract sprite, AI remove background, remove background, outline, shadow, gradient, colour) show the image feeding their input on the left (for remove background, the white render) and their result on the right, each fitted into its pane, with no captions; every picture frame (result panes, the drawing stage of image edit, extract and draw, the composer viewport, the part cells) has the same frame and soft shadow; the row under the pictures holds only their switches at the right: `Transparent bg` (image gen and image edit) and `Crop` (image edit puts its drawing tools in that row too). The switch turns the transparent background on; the method and its settings are in the parameters after the model and the seed, shown while it is on. Remove background has `Crop` alone: it is always transparent. The `Image nodes` row of the AssetsLine dialog (the gear) switches every such card between `Side by side` and `Compare` at once; the choice is kept per user in `Work/Pipelines/ViewPrefs.json`. Compare puts both images into one view split by a vertical divider, the input left of it and the result right of it; pressing anywhere in the view moves the divider there (its position is kept per node for the session). A card shows two panes while a crop frame is edited or either image is missing, and the extract card never compares (one source, many parts); both modes give a card the same height. The divider is a dark hairline one screen pixel wide at any zoom with a faint light halo, and a small dark grip of 5 × 18 screen pixels with a light ring, at 60 % until the cursor is over it; the grip keeps its screen size when zooming in and stops growing on the canvas at 1.5 times its size when zoomed far out. A new card of these types starts 480 units wide with an automatic height (0 in the file: it follows the content); dragging a side edge keeps the height automatic, the top or bottom edge sets it.
- **AI image edit** has the same painter: the drawing stage over the input on the left and the result on the right (or the compare view), then under them the drawing tools (brush, eraser, frame, colour, size and opacity sliders, undo / redo / clear). From a card width of 560 the tools and the switches share one row, the switches at its right end and the sliders taking the width left; a narrower card puts the switches on a row of their own under the tools. The draw card keeps its tools above the picture; the extract card draws nothing. Comparing, the stage itself is split: only a strip about 12 screen pixels wide over the divider drags it, and the brush draws on the input side only.
- **Edit region of AI image edit.** The region tool of the drawing toolbar (always there) sets a frame the model works inside (`editRegion`, fractions of the input; part of the node signature). Picking the tool without a frame creates a centred one (a quarter of the image from each side); with the tool on, the frame is moved and resized by its handles like an extract region, and the trash tab on its corner removes it and brings the brush back. The brush and the eraser work as before, with the frame shown but not editable. Everything outside the frame is dimmed; comparing, the frame spans both halves, above the divider while the region tool is on and under it otherwise. While a frame is set the transparent switch is gone and the parameters show `Frame set: the background stays as it is` after the model and the seed. A run then sends the model the input and the drawing over it cropped to a context box (the frame grown by a quarter of its longer side, at least 16 px, clamped to the image) with a request to keep the crop's margin, stretches the answer back over the box and blends it in: fully inside the frame, fading linearly to nothing at the box border, alpha included; pixels outside the box stay as they were. A frame narrower or lower than 2 % of the image counts as none. The transparent background is not used while a frame is set (one generation; its settings stay stored and apply again without the frame); the crop of the result applies as before. **AI remove background** keeps the subject and paints everything around it over with a flat backdrop, which is then keyed out or matted away.
- **AI upscale** enlarges an image with the image model: it is redrawn at the new size with added detail, and the prompt says which details and how. The card shows the input beside the result, then the size row: `×2` / `×3` / `×4`, or `Size` with W, the aspect lock and H (locked, H follows the input's shape and typing H sets the W that gives it; unlocking keeps the H on view), and at the right `input -> output` once the input size is known; both sides are capped at 8192. The parameters hold the model and the seed; a model that answers at about 1K gets a note that the rest is resampled (the Gemini 3 image models render 2K / 4K themselves). A run takes one generation: the input is padded with its edge pixels to the nearest frame the model renders (a transparent input is first put on flat gray), the model is asked for that frame and, when it can, for the 1K / 2K / 4K resolution that covers the target, the padding is cut off the answer and it is resampled to the exact size; a transparent input keeps its own shape, its alpha scaled to the target.
- **AI extract sprite** cuts several parts out of one image: under the toolbar the source is on the left and the grid on the right, a cell per part with its result, its name under it (edited in place for the selected part) and, in the corner, a regenerate button that re-runs that part alone and a delete button; with several parts each part's output port sits on the bottom-right corner of its cell, so a link leaves the result it carries; such a link is drawn over the cards (the other links stay under them), so its start inside the card stays visible. Clicking a cell selects the part; the source shows every part's box numbered, the selected one with its handles and a remove tab in its corner (the part outside the box is shaded), and clicking another box selects that part. The card has no drawing: no tool row, no drawn layer, and the boxes are edited without picking a tool; a drawing left in a pipeline from before is neither shown nor sent to the model. `+ Add part` adds one and `Auto split` asks the model to list the parts of the image and fills the grid with their boxes. Every part is an output port of its own, named after it, so links follow a part through renames; each part is run, cached and previewed on its own, so editing or re-running one part leaves the others in place. While a run computes a part, its cell is dimmed with a turning ring over it; a part that failed gets a red frame while the rest of the node still runs (a node with one part shows the ring while the node runs). Parts served from the cache show nothing.
- **Background of each part.** The extract card's `Transparent bg` switch sits at the right end of its actions row (`+ Add part`, `Auto split`) when the card is at least 400 wide, on a line of its own under it when narrower. The switch and the method rows in the parameters (`Transparent bg mode`: `White / black x2` / `Chroma key x1`, and for the chroma key the key colour, `Tol`, `Soft` and `Spill`, after the model and the seed) belong to the whole node until a part gets settings of its own. With several parts a `Settings for` row above the method rows switches the selected part between `All parts` (it follows the node) and `This part` (it gets a copy of the settings it uses now, which the rows below then edit); `All parts` drops the copy again. A part with its own settings has a dot before its name in the grid, and selecting another part switches the switch, the row and the rows below to that part. With one part there is no such row - the node's settings are the part's. A part switched to its own settings is out of date until it runs again (its cache key follows its own settings now); switched back, it finds its earlier result. The settings are stored with the part in the pipeline file, so AssetsLine and the Unity plugin show and run them the same way.
- **Background rendered by the model.** Some models render a transparent background themselves: the OpenAI GPT Image models (`gpt-image-1`, `gpt-image-1.5`, ...) and, through OpenRouter, `openai/gpt-image-...` (all but `openai/gpt-image-2`), `openai/gpt-5-image`, `openai/gpt-5-image-mini` and `sourceful/riverflow-v2.5-pro`. With such a model the image cards (generate, edit, extract, remove background) keep the `Transparent bg` switch but show no method and no key colour, `Tol`, `Soft` or `Spill` rows; with the background on, the note `Rendered by the model` stands in their place. The result takes one generation and is used as it comes. The method and its values stay in the node, so another model brings the rows back as they were. The same holds for a part of the extract card with settings of its own.
- A node shows what comes into it before anything runs: source nodes (text, image, audio) hold their value from the config at once, and a card refreshes as soon as a link into it is added or removed. An input linked to one part of an extract node shows that part's own result, and nothing while the part has none - never another part (`PipelineEditor::GetInputValueById`, the rule AssetsLine and the Unity plugin follow).
- **Model row.** The field shows the product name (`Gemini 3.1 Flash Image · Nano Banana 2`, `Google Veo 3.1`, …, the same names as in AssetsLine) and, on an image node whose model renders the transparent background itself, an `α` badge; the config keeps the model id. A click opens the model menu (a second click, a click outside or Escape closes it): a search field that has the focus, chips `All` plus one per provider when the list has two or more (for image nodes also `α Transparent bg`), and the models in groups - `Current` (a value outside the list, e.g. one chosen in AssetsLine), `Recent` (the last 5 picks for this kind of list: text, image, video, Gemini TTS, ElevenLabs; kept in `Work/Pipelines/RecentModels.json`), `Google Gemini`, `OpenAI`, `Kling`, `ElevenLabs`, then `OpenRouter · <vendor>`. The OpenRouter vendor groups start folded except the one holding the node's model; a header click folds or unfolds a group until the menu closes; a search or the `α` chip opens every group with a match and hides the others. A row shows the name without the provider part, the id, a check mark on the node's model and the `α` badge. The search finds a model when every word is in its name, full name, id or group, as typed or with punctuation left out (`gpt55` finds `gpt-5.5`); ↑/↓ move the highlight, Enter picks, and typing an exact id highlights that model. Text without spaces that is no listed id adds a row `Use "<text>" as model id`, which stores any id. The menu opens on the node's model, below the field or above it when there is more room, at least 320 px wide and at most 440 px tall, above every card; the canvas does not move or take keys while it is open. The text and image lists hold the Gemini models, then OpenAI's (`GPT-5.5 · OpenAI`) and OpenRouter's (`OpenAI: GPT-5.5 · OpenRouter`). The id names the provider: `vendor/model` is OpenRouter, `gpt-…`, `o3…`, `chatgpt-…` and `dall-e-…` are OpenAI, any other id is Gemini. A model that both its own provider and OpenRouter offer runs where a key is set: the own provider first, the other one when its key is missing (the log says so).
- **Prompt writer target.** The `Target` field of the prompt writer shows the icon of the node the prompt is written for and the target's name; a click opens a menu in the model menu's look, without the search: one row per target (image, video, text, sound effect, music, spoken line) with that node's icon, the name and a hint under it, the current one checked. ↑/↓ move the highlight (wrapping), Enter picks, Escape, a click outside or a wheel outside closes it; a click on the field of the open menu closes it too. The hint of the current target also stays under the field. The system prompt field of the parameters spans the card and wraps its text.
- **Composer** arranges several image inputs on a fixed work area: select a layer on the stage, move it, scale and rotate it with the frame handles (`Shift` moves along one axis); the card has the layers list on the left, right under the `out` port row, and on the right the work area with its parameters under it, with a splitter between them (`layersPanelW`, 200-560, dragging it right widens the list). The list shows `Layers · N`, a row per layer from the front one down, each with its settings fold-out, visibility, thumbnail, name, duplicate, forward / backward, reset, delete and a grip, then a `+ input` row. Each input's port sits on the card's left edge, on its layer row (a copy shares its source's input and has no port); the port rows hold only `out`. A click on `+ input` adds an image input, the new front layer; a link dropped on it creates the input and connects it. Dragging a row's grip moves it in the stack: a line shows where it lands, the dragged row is dimmed, and the release writes `layerOrder` (landing in place changes nothing). The list never scrolls: the card grows with it, a height set by hand above that goes to the work area. The parameters under the work area are captioned groups, right-aligned and wrapping onto a second line in a narrow card: `Canvas` (W × H), `Zoom` (- % +), `Flip` (only while a layer is selected) and `Background` (`Preview` and `Output`, each with its colour). Focusing a layer's name field, by a click or the keyboard, selects the layer and keeps the focus in the field. The per-layer settings hold size with aspect lock, opacity and a 9-slice with insets and corner scale. `BG` previews against a colour, `Out BG` fills the rendered output. `Save layers to Assets` writes every layer as its own PNG asset into the chosen folder with the name prefix, like a finish node does with its result; the composed image itself goes through a finish node.
- **Audio and video results** play inside the card: play/pause, seek slider, elapsed and total time, loop toggle and volume slider. Audio goes through the engine sound system; video frames and the audio track are extracted with ffmpeg on first view into `Work/Pipelines/cache/<pipeline>/video/<hash>/` (a frame atlas plus a WAV) and reused afterwards.
- **Finish** nodes show what reaches them before anything runs and have no play button of their own. They pick the folder inside `Assets` (typed or chosen from the folder list behind `…`) and the file name; the card shows the full path the node writes to, whether the file already exists and the size of the incoming result (with the resize target when resizing is on). The resize fields show the size the image is saved with (after the crop); turning `Resize` on, or typing a size, starts from it, and the link button between the fields keeps the aspect ratio, and the locate button selects the saved asset in the assets window. `Save to Assets` on the card, or `Run all`, writes the file, then the editor rebuilds assets so it is usable in scenes right away.

Local nodes (text tools, image effects, draw, composer, finish) re-run automatically after a change, taking the last rendered result of an upstream provider node even when its cache entry is gone; provider nodes run on their play button or `Run all`. Results are cached by a content signature that follows the node config and every upstream node, so unchanged nodes are not re-requested; `Clear result` in the node menu drops the cache of one node.
